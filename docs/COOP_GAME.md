# 逃生小队（0.23.0 候选）

本文件记录房间规则和验收边界。公开站点的实际版本、部署 SHA 和 Actions 结果以 [Issue #67](https://github.com/lingyunmo/nwaxz/issues/67) 的发布记录为准。

## 入口和生命

极限恐怖保留绘制封面，入口为单人游戏、多人游戏、操作、返回。继续、新游戏、导入导出只在单人子菜单。多人选择昵称和四种头像之一，创建私有房间或输入房间码加入，不提供匹配、房间列表和多人存档。

房间最多三人，至少两人且所有人场景就绪才能开始。人数在开局固定：两人各两条命，三人各一条。掉线、队长转移和重生均不增加生命。钥匙、搜索进度、机关及水晶库存共享；位置、体力、疲劳、视听分数、干扰和生命独立。冻结、显形、净化是队伍效果，计时只推进一次。

被抓只扣受害者生命、播放其捕获 CG。有剩余生命时点击重生，服务器选择合法且远离猎手的上层出生点，不重置队伍任务和猎手；没有生命则旁观仍在局中的队友。所有未淘汰、未退出成员进入出口后胜利；全部失去机会则失败。旁观不允许移动、操作机关或消耗水晶。

## 同步和判定

- 使用现有 nwaxz Node 服务维护权威状态，玩家设备负责 Babylon 画面。每个活人完整推进 20 Hz 的移动和个人感知，整个房间只推进一只猎手、一个世界时钟和一套地下技能。
- 同源 HTTP 输入最多每秒十次，连续移动与离散操作分开排队；20 Hz 服务器步进，约 8 Hz SSE 快照。大厅不变时仅低频保活。客户端只平滑画面位置和本地视角，不推进权威 AI、物品或任务。
- 100 追击、45 警觉、1.5 倍感知和六秒警觉沿用单人规则。HUD 追击锁定不作为新的 AI 证据；刷新目标必须有当前有效视听或光照线索。失去线索后沿最后目击点搜查，能甩开；队友真实新线索也能吸引猎手。石子、玻璃、机关和概率脚步调查不要求先攒到 45。
- 地下感测/瞬移共享一套轮次，选择一名地下成员作为目标；感测按该成员实际位移记忆判定静止/移动，不由另一个跑动队友代替。命中隐藏者能搜其柜子；瞬移仍从原安全合法落点池抽取。队友暴露时显示其编号，不把所有人的个人暴露值都写满。
- 右侧显示稳定编号、绘制头像、昵称和生命。队友身体八方向并正常受墙遮挡，头顶编号 1/2/3 单独发光透墙。自己的延迟位于头像卡内，使用真实 HTTP 往返时间；迟缓、断线和房间关闭分开提示。

## 生命周期和边界

令牌仅返回本人，保存在当前页面内存，通过 Authorization 发送，不放 URL 或广播。断流有 30 秒重连宽限；主动退出即离开，大厅腾位、队长转移，对局继续。刷新/关闭页面会丢失内存会话，不等于保存进度；服务更新或进程重启会结束未保存房间。

默认最多四间房，可由 `NWAXZ_COOP_MAX_ROOMS` 配置但硬上限 32。限制创建频率、同源房间容量、会话输入/操作频率、消息大小和 SSE 背压。两分钟无活动大厅、断线空房及结束一分钟的房间回收。版本不匹配拒绝加入。坐标、存档、生命和目标位置不能由客户端提交。代理 IP 只在私有/回环上游且地址合法时用于限流；沿用 NPM common-net 入口，没有公开新端口。

多人不会写单人进度或纪录。暂停、地图和纸条只阻止本机输入，房间继续运行；离线可继续单人，不能建立联机房间。云端存档同步仍未实现。

## 本地预算与证明

`node --expose-gc server/coop-load.mjs` 在本机以完整模型测试三人房，含 20 Hz 计算和 8 Hz JSON 序列化；自动复活的负载夹具保证采样期间持续运算，不作为通关证明。正常探索和全部 833 个合法地板格分别采样，三个样本取中值。

最终源码的三次采样中位数：一房约占单核 0.63%，SSE 数据约 63–142 KB/s；四房合计约单核 1.88%–2.65%、254–566 KB/s。静态每房内存因 GC 噪声无法可靠分摊，不能声称为零。数据不含 HTTP/TLS、协议头、丢包、真实网络和首次媒体下载；本机预算不能当作线上机器容量保证。保留现有容器资源限制，不更改其他服务。

独立参考玩家通过正常输入、碰撞、交互、有限水晶和有限生命推进，两人固定种子 202 完成完整地下往返：第一名队员失去两条命，合法藏柜的队友接续共享任务逃出，约 398 秒。地下感测和瞬移保持启用。三人同种子真实失败，三名成员各消耗一条命；该记录验证失败和旁观边界，不能宣称三人路线已经通关。固定随机初态不赠送物品、不搬运玩家、不关闭 AI。测试机器人不等同真人协作或真机性能。
