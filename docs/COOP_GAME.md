# 逃生小队（0.24.0 候选）

本文件记录房间规则和验收边界。公开站点的实际版本、部署 SHA 和 Actions 结果以 [Issue #72](https://github.com/lingyunmo/nwaxz/issues/72) 的发布记录为准。

## 入口和生命

极限恐怖使用绘制封面和角色，侧栏提供单人游戏、服务器、房间、好友、个人资料、设置和操作。继续、新游戏、导入导出只在单人子菜单。服务器显示实际 HTTP 往返延迟与 0/8 房间占用；房间列表区分公开房和密码房，等待中且有空位才可加入。房间内显示三位队员全身和真实就绪状态；至少两人且全部准备好后由队长开始。不提供匹配和多人存档。

房间最多三人，至少两人且所有人场景就绪才能开始。人数在开局固定：两人各两条命，三人各一条。掉线、队长转移和重生均不增加生命。钥匙、搜索进度、机关及水晶库存共享；位置、体力、疲劳、视听分数、干扰和生命独立。冻结、显形、净化是队伍效果，计时只推进一次。

被抓只扣受害者生命、播放其捕获 CG。有剩余生命时点击重生，服务器选择合法且远离猎手的上层出生点，不重置队伍任务和猎手；没有生命则旁观仍在局中的队友。所有未淘汰、未退出成员进入出口后胜利；全部失去机会则失败。旁观不允许移动、操作机关或消耗水晶。

## 同步和判定

- 使用现有 nwaxz Node 服务维护权威状态，玩家设备负责 Babylon 画面。每个活人完整推进 20 Hz 的移动和个人感知，整个房间只推进一只猎手、一个世界时钟和一套地下技能。
- 取名、开房、加入通过同源 HTTPS；对局使用一条 WSS 双向长连接，收发输入、操作、快照和心跳。输入最多约每秒十批，未改变时每 200ms 保活；不按步伐或渲染帧发送 HTTP。服务器 20 Hz 校验和推进共享世界、约 8 Hz 发快照，大厅状态未变时不重发整局。
- 本地每渲染帧即时转头、按同一碰撞规则预测移动；收到权威位置后回放有限延迟内的输入，并衰减画面误差。藏柜、复活、瞬移、换旁观对象时重置预测。客户端不决定 AI、物品或生命。头像卡状态未变不重建 DOM；普通操作被拒绝不会被误报成断流。
- 100 追击、45 警觉、1.5 倍感知和六秒警觉沿用单人规则。HUD 追击锁定不作为新的 AI 证据；刷新目标必须有当前有效视听或光照线索。失去线索后沿最后目击点搜查，能甩开；队友真实新线索也能吸引猎手。石子、玻璃、机关和概率脚步调查不要求先攒到 45。
- 地下感测/瞬移共享一套轮次，选择一名地下成员作为目标；感测按该成员实际位移记忆判定静止/移动，不由另一个跑动队友代替。命中隐藏者可调查其位置，但隐藏期间一律不能捕获；瞬移仍从原安全合法落点池抽取。队友暴露时显示其编号，不把所有人的个人暴露值都写满。
- 右侧显示稳定编号、绘制头像、昵称和生命。队友身体八方向按彼此实际位置选择，原地转镜头不换面；正常受墙遮挡，贴图明确启用透明采样并保留暗处可读性。头顶编号 1/2/3 独立发光透墙，画布按正向上传。自己的延迟位于头像卡内，使用同一条 WSS 的真实 ping/pong 往返时间；迟缓、断线和房间关闭分开提示。

## 生命周期和边界

令牌仅返回本人，保存在当前页面内存，通过 WSS 的第一条认证消息发送，不放 URL 或广播。断流有 30 秒重连宽限；主动退出即离开，大厅腾位、队长转移，对局继续。刷新/关闭页面会丢失内存会话，不等于保存进度；服务更新或进程重启会结束未保存房间。普通操作请求错误保持连接，认证或版本错误终止重连并提供退出入口。

CSP 仅显式允许当前 Host 的 ws/wss，不开放任意连接目标；单独的 `connect-src 'self'` 并不在所有浏览器中涵盖 WebSocket，参见 [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src)。

默认及硬上限均为八间房，可用 `NWAXZ_COOP_MAX_ROOMS` 下调。限制创建频率、同源房间容量、会话输入/操作频率、消息大小和发送背压；WSS 限制未认证连接、五秒认证期限、同源 Origin 和 8KiB 消息。两分钟无活动大厅、断线空房及结束一分钟的房间回收，最长房间生命周期 30 分钟。版本不匹配拒绝加入。坐标、存档、生命和目标位置不能由客户端提交。代理 IP 只在私有/回环上游且地址合法时用于限流；沿用 NPM common-net 入口，没有公开新端口。

多人不会写单人进度或纪录。暂停、地图和纸条只阻止本机输入，房间继续运行；离线可继续单人，不能建立联机房间。云端存档同步仍未实现。

## 本地预算与证明

`node --expose-gc server/coop-load.mjs` 在本机以完整模型测试三人房，含 20 Hz 计算和 8 Hz JSON 序列化；自动复活的负载夹具保证采样期间持续运算，不作为通关证明。正常探索和全部 833 个合法地板格分别采样，三个样本取中值。

0.24 候选模型的三次采样中位数：一房约占单核 0.78%，状态 JSON 载荷约 64–143 KB/s；八房合计约单核 3.35%–4.22%、515–1142 KB/s。静态每房内存因 GC 噪声无法可靠分摊，不能声称为零。数据不含实际 socket 发送、TLS、帧头、丢包、真实网络和首次媒体下载；本机预算不能当作线上机器容量保证。保留现有容器资源限制，不更改其他服务。

独立参考玩家通过正常输入、碰撞、交互、有限水晶和有限生命推进，两人固定种子 202 完成完整地下往返：第一名队员失去两条命，合法藏柜的队友接续共享任务逃出，约 398 秒。地下感测和瞬移保持启用。三人同种子真实失败，三名成员各消耗一条命；该记录验证失败和旁观边界，不能宣称三人路线已经通关。固定随机初态不赠送物品、不搬运玩家、不关闭 AI。测试机器人不等同真人协作或真机性能。

## 游客身份与好友

首次进入逃生大厅自动申请九位 UID，设置昵称与四款角色之一。浏览器保存随机游客令牌，服务器只保存 SHA-256 摘要；UID 是可公开的好友编号，不能用 UID 登录。身份令牌只经 HTTPS Authorization 发给同源接口，不进房间列表、WSS URL 或广播。游戏存档格式重置不会删除这项独立身份凭据；清除浏览器数据会失去该游客身份，目前没有跨设备迁移和找回功能。

好友申请经对方接受后双向建立，可移除、查看在线和邀请入房。邀请五分钟有效、绑定接收者 UID 和原房间实例，仅邀请人仍在等待中的房间才可使用；有效邀请允许该好友免输房间密码，成功加入后消耗。移除好友、邀请人离房、房间开始/关闭都会撤销相应邀请。两端好友均限100，待发申请限25；新游客和接口有独立频率限制。房间密码仅保存随机盐加 scrypt 摘要。

资料、好友与申请写入独立 `nwaxz_profile-data` Docker 卷中的 SQLite；只创建新表，不迁移、读取或修改其他项目数据库。生产必须设置 NWAXZ_PROFILE_DB，禁止静默退回内存。在线状态和邀请是短期内存状态，重启失效；房间仍随服务重启结束。大厅每15秒刷新资料/列表，比赛的移动同步不访问 SQLite。云端游戏存档仍未实现。

## 界面和玩法一致性

总暴露值保留，展开仅显示声音/灯光/视觉三条，不常驻计算贡献或数值。水晶只显示冻结/显形/净化短名；操作说明与纸条保留规则。地图仅给已探索区域加汉字，未知房间不泄露。敌方卡缩小，暂停按钮放大。HOT 为入口装饰，不表示实时在线人数。

衣柜内即使被目击或感测命中也不捕获。猎手行走朝向等于真实位移方向，八向贴图按与观察者的位置夹角选择。显形叠层穿楼板并提示上/下层；CG 不主动因失焦暂停，浏览器若挂起视频，返回时按墙钟追赶或结束；玩家手动暂停仍有效。
