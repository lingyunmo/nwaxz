# 游戏更新

生产worker由 `/game-worker` 提供，内容是构建的 `dist/sw.js`，根作用域，响应 `Cache-Control: no-store, max-age=0`。无扩展名用于避开公网 `.js` 的长期静态缓存策略；不改变共享网络或其他服务。兼容旧 `/sw.js` 源站同样返回no-store，但代理/边缘层仍需独立核对。2026-10-23只读检查确认NPM的nwaxz主机Cache Assets已关闭、自定义配置为空，未改动代理；不能仅凭响应头将31天缓存归因于此开关。

注册使用 `updateViaCache: none`。启动、在线恢复、页面回前台/获得焦点和每分钟检查新worker。离线启动复用已有注册，避免为检测更新强制联网。新包完整安装后，首页/选关且没有打开对话框时激活并刷新一次；游玩、暂停、极限恐怖及CG期间延后到安全菜单。同源其他标签激活worker时，本标签也按同样条件延后刷新。首装离线包不额外刷新。

更新不会清除站点数据、IndexedDB、localStorage或导出备份。视频使用独立运行时缓存；更换视频需使用新的版本化文件名并调整缓存规则。视频按需缓存，基础更新不等待约14MiB影片。

`ops/updates-browser.mjs` 在独立Chromium及临时测试服务切换真实两份worker/首页，验证游玩时保留旧页、返回菜单只刷新一次、v1成绩/逃生存档/设置严格一致、离线重启不循环。测试不访问用户浏览器数据。`ops/cinematics-browser.mjs` 验证原声静音状态、自然结束、跳过、三种随机结果、仿真冻结、播放受限恢复、完整缓存的离线206字节范围播放。

旧客户端在获得本批代码前仍使用旧检测逻辑。如果代理尚将旧worker缓存31天，需对nwaxz主机取消该规则并核对旧URL缓存；不能以新代码测试代替旧客户端迁移验收。具体发布结果记录在[Issue44](https://github.com/lingyunmo/nwaxz/issues/44)。
